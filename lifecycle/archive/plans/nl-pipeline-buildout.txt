## 0. CONTEXT & GOALS

### Problem statement
A 3B (Marika) / 7-14B (Radagon) base is unreliable at emitting a complete,
schema-valid tool call for an arbitrary request in ONE turn. Today the entire
"understanding" step is a single `responder(messages, tools)` call classified by
`core/agent/router.py`. When it misses, the loop re-asks the SAME hard question.
The proposal decomposes understanding into intent classification + narrow
per-slot extraction + deterministic assembly, then adds deterministic
verification with op-class-keyed retry.

### The single most important framing (from the brainstorm — read it)
The spec's execution half is ALREADY BUILT and correct:
  - `core/tools/__init__.py::run_subprocess` is `subprocess.run(list)`, shell-free.
  - `core/agent/permissions.py::classify` is the hardened, argv-aware, default-deny
    gate (READ->ALLOW, WRITE->CONFIRM, DESTRUCTIVE->CONFIRM_TYPED, non-interactive
    write/destructive->REFUSE).
  - `core/agent/repl.py::run_turn` is the audit + gate + dispatch spine.
Therefore we DO NOT hand-roll fork()/dup2()/pipe(). We DO NOT build a second
executor. The durable value is concentrated in **[1] intent + [2] slots
(decomposed understanding)** and **[6] deterministic verification**. Everything
we build must terminate by producing the SAME validated `ParsedCall` /
synthesized-argv the current path produces, and hand it to the EXISTING
`synthesize_command -> permissions.classify -> registry.dispatch -> AuditLog`.

### Success criteria (measurable)
1. On the hard/compound cases in `bench/cases/`, the decomposed strategy raises
   tool-call validity rate vs. single-shot by a measurable margin (target: close
   the gap on cases single-shot currently MISSes), WITHOUT regressing any
   currently-passing easy case.
2. p50 latency of a COMMON single op ("restart nginx", "is nginx failing")
   is UNCHANGED vs. today, because decomposition never runs on the fast path
   (it is an escalation tier). Measured on mossad (Section 9 checkpoints).
3. Zero new code path can reach `registry.dispatch` without first passing through
   `permissions.classify` with the same synthesized argv today's path uses.
   (Enforced by test: Phase 5 + Phase 1 invariance suite.)
4. Destructive-class ops are NEVER auto-retried by verification (Phase 6 test).
5. All existing tests (`tests/test_repl.py`, `test_router.py`, `test_permissions.py`,
   `test_synthesize_command.py`, `test_integration_invariance.py`,
   `test_invariance_baseline.py`, `test_dispatch.py`) stay green at every phase
   boundary.

### Non-goals (explicitly out of scope)
- Replacing `router.py` or the FROZEN 0002 tool-call contract (Option A — rejected).
- A second execution path / hand-rolled fork+exec bundle (Option B — rejected; R1).
- Cross-tier model escalation as a universal rung (Marika box likely has no larger
  weights; on 2x3060 Ti a 3B + 14B do not co-reside — cold-swap cost). Marika's top
  rung is "ask the human"; Radagon-class hardware may add a larger-model retry.
- Model state across a long sequence (already honored — model is stateless per call).
- Full man-page coverage. The man-page track is best-effort + human curation of a
  top-N list, build-time only, and is NOT on the critical path.

### Assumptions made
- A1: DEFAULTS/RANGES live in the new assembler (Phase 2), sourced from
  `ArgSpec.default` (which exists in `core/tools/__init__.py` but is not centrally
  applied today). This is a USE of the frozen contract, not a change to it.
- A2: "Confidence" from the OpenAI-compat Ollama endpoint is UNVERIFIED (open
  question). The plan does NOT assume logprobs. Confidence is synthesized from
  concrete deterministic signals first (intent match distance, required-slot
  completeness, assembler validation success), and only optionally from
  self-consistency sampling. A single-shot MISS is itself the primary escalation
  trigger and needs no confidence dial.
- A3: Intent match may be done via the 0003 sqlite-vec index (embedding similarity
  over schema descriptions — a retrieval, not a generation call) OR a model call.
  Phase 3 spikes both; the seam is identical either way.
- A4: The man-page track (Phase 9) can be deferred entirely without blocking
  Phases 1-8. The curated 13 tools remain the fast path.
- A5: `synthesize_command(call)` in `repl.py` is the canonical argv renderer and
  is reused verbatim by the pipeline. The assembler produces `ParsedCall`, NOT a
  shell string; argv rendering for the gate stays in `synthesize_command`.

## 1. ARCHITECTURE OVERVIEW
=====================================================================

### How this fits (Option C from the brainstorm — CONVERGE on the spine)
```
                 user_input
                     |
          Repl.run_turn (core/agent/repl.py)   <-- ONE integration seam
                     |
          +----------+-----------------------------+
          |   UnderstandingStrategy.propose(...)   |   (NEW protocol, Phase 1)
          +----------+-----------------------------+
          |                                        |
   [default] NativeToolCallStrategy       [opt-in] DecomposedStrategy
     - responder(messages, tools)           core/agent/pipeline/  (NEW, Phases 2-4)
     - Router.route()                          [1] intent classifier
     - byte-identical to today                 [2] parallel slot extraction
          |                                     [3] deterministic assembler
          |                                          -> emits ParsedCall(s)
          +--------------------+--------------------+
                               |
                     list[ParsedCall]  (SAME shape both strategies)
                               |
        ===== UNCHANGED HARDENED SPINE (repl._dispatch_calls) =====
          synthesize_command(call)   (repl.py, reused verbatim)
                -> permissions.classify(argv, ExecContext)   [THE ONLY GATE]
                -> _resolve_gate (ALLOW / CONFIRM / CONFIRM_TYPED / REFUSE)
                -> registry.dispatch(tool, op, args)          [subprocess.run(list)]
                -> AuditLog.write (I4, every op incl. refusals + misses)
                               |
        [6] verification (Phase 6): a READ op via the SAME spine, compared to
            intended state; bounded retry keyed on OpClass; destructive -> escalate
                               |
                     English answer terminates the turn
```

### Affected services
- core/agent  : NEW pipeline package; ONE seam added to repl.py; 0004 decision doc.
- core/tools  : UNCHANGED contract. Man-page track (Phase 9) REGISTERS generated
                tools in the frozen ToolSpec/OpSpec/ArgSpec shape; no schema change.
- bench       : extended with a labeled intent+slot set + compound cases.
- distro/models: no change for Phases 1-8. Man-page schema artifact is a build-time
                 checked-in file (Phase 9); the shipped box never parses troff.

### Invariants this plan must preserve
- I1 No egress: every extra inference call is localhost Ollama via the injected
  responder. N slot calls = N x LOCAL compute, never new egress.
- I2 No AI/LLM/model/agent language in any user-facing string (plan/confirm/verify
  surfaces speak plain Linux — they already do).
- I3 The gate is `permissions.classify`, resolved BEFORE every write/destructive.
  The pipeline NEVER re-implements, weakens, or bypasses it (R1 — the #1 risk).
- I4 Every attempted op (incl. verification reads, fallback attempts, misses) writes
  exactly one append-only JSONL audit record.
- I5 Fresh context injected every turn; context invalidated after a successful
  mutation (verification reads must see post-mutation reality).
- I6 No tier/product names in the framework; TierConfig is injected.
- I7 Marika (3B) and Radagon (7-14B) share one architecture; the difference is
  model size + slot-worker depth + escalation ladder, not structure.
- I8 Reads feel instant (ALLOW, no friction) — decomposition must not touch the
  fast path.

### PHASE 6: Deterministic verification + op-class-keyed bounded retry
---------------------------------------------------------------------
Prerequisites: Phase 5.
Deliverables:
  - core/agent/pipeline/verify.py:
      * `verify(call, result, registry, exec_ctx, audit) -> VerifyOutcome` that runs
        the tool's OWN READ op (via the SAME spine: classify(ALLOW) -> dispatch ->
        audit) and compares to intended state.
      * Retry policy keyed on OpClass (from the brainstorm table):
        services/packages/files/firewall/users -> idempotent, auto-retry up to
        ERDTREE_RETRY_MAX; network -> partial; disk format/partition/dd/wipe and any
        DESTRUCTIVE -> NEVER auto-retry, ESCALATE to a human with a concrete error.
Steps:
  1. Map each core tool's write op to its verifying read (systemctl is-active,
     rpm -q, stat/test -e, firewall-cmd --query-service, id <user>, ip addr show).
  2. Run the read through classify (it lands ALLOW) + dispatch + audit (I4). Compare.
  3. On failure: if op_class is idempotent -> retry the write (bounded); else ->
     escalate (no retry). Invalidate context between attempts (I5).
  4. Gate the whole feature behind ERDTREE_VERIFY (default off until mossad-proven).
Validation:
  - test_pipeline_verify.py: an idempotent failing write retries up to the cap and
    stops; a DESTRUCTIVE failing op NEVER retries and returns an escalation outcome;
    every verification read writes an audit record.
Risks / Edge cases:
  - R3: auto-retrying `mkfs`/`dd`/`userdel` is catastrophic. Mitigation: retry keyed
    on op class; destructive path has NO retry branch (assert in test).
  - A verifying read that itself mutates (must not exist). Mitigation: only use ops
    declared READ in the registry; the classifier confirms ALLOW.
Subagent orchestration:
  - Execution shape: [SEQUENTIAL — depends on Phase 5]
  - REQUIRED subagent_type: general-purpose
  - REQUIRED model: opus (safety-critical retry taxonomy; a mis-keyed class is a
    catastrophic auto-retry — worth the stronger model)
  - Run in background: no (Phase 8 re-planning builds on verify outcomes)
  - Brief template:

## 5. API CONTRACT
=====================================================================
No network API. The internal "contract" is the UnderstandingStrategy protocol:
  propose(user_input, snapshot_text, messages, tools, responder, router)
      -> StrategyResult(calls: list[ParsedCall], misses, english_content, source)
Both NativeToolCallStrategy and DecomposedStrategy implement it. ParsedCall is the
FROZEN router shape (call_id, tool, operation, args, permission_class) and is the
ONLY thing that flows into the unchanged gate/dispatch/audit spine.

## 6. WORKER / QUEUE CHANGES
=====================================================================
No job queue. The only concurrency is the slot-worker thread pool (Phase 4),
capped by ERDTREE_SLOT_WORKERS and Phase-0 findings. All calls are localhost
Ollama (I1). Idempotency of RETRIES is enforced by op-class keying (Phase 6),
not a queue.
